# Live D435i smoke test — 2026-09-24

The `dev` branch (base `a45e0ba`, plus `sync_odometry` support) ran on a
physical RealSense D435i with YOLOE inference on an RTX 3090. The camera was
anchored to a fixed world pose; this is a stationary-camera demonstration,
not a test of camera tracking or SLAM accuracy.

Environment: ROS 2 Lyrical, Python 3.14.4, PyTorch 2.10.0+cu128,
torchvision 0.25.0+cu128, Ultralytics 8.4.162, YOLOE v8l segmentation,
RealSense ROS driver 4.58.4 / SDK 2.58.4. The D435i reported firmware
5.13.0.50 and serial 103422070404. Factory CameraInfo supplied 640×480
intrinsics with nonzero focal lengths and zero distortion coefficients.

The workspace's `supermap_bringup/d435i_supermap.launch.py` starts the
camera, a static `map -> camera_link` transform, SuperMap, and RViz.
SuperMap receives RGB, CameraInfo, and color-aligned 16UC1 depth through
the actual ROS message synchronizer with `sync_odometry: false`.
Driver TF supplies the calibrated camera optical frame. No odometry
messages or pre-baked detections are supplied.

An independent subscriber measured the following over 15.04 seconds:

| Output | Messages | Approximate rate |
| --- | ---: | ---: |
| Color image | 226 | 15 Hz |
| Color-aligned depth | 227 | 15 Hz |
| Semantic point cloud | 76 | 5 Hz |
| Object box/label markers | 75 | 5 Hz |
| Annotated RGB | 15 | 1 Hz |

The final sampled semantic cloud contained 5,221 points in `map`. Markers
included monitor, keyboard, bottle, and person labels, with active,
occluded, and disappeared states. A keyword query returned an instance ID
and map coordinates, and the save service wrote 15 instance records to
`map.json` / `map_arrays.npz`. No navigation controller was connected.
The keyword client can return remembered/disappeared objects; this check
establishes request/response transport, not relational or temporal reasoning.

Runtime logs showed mapping at approximately 15 Hz and detector updates
at 1 Hz. Warm GPU inference on a blank frame took 17 ms. The first live
inference exceeded its two-second deadline during initialization; later
frames recovered and output continued. The blank-frame timing is not a
benchmark of segmentation on the live scene.

Validation: 200 tests passed in the system ROS environment, including
three new regressions covering actual RGB-D transport without odometry,
the retained default odometry gate, and rejection without camera TF.
All 25 ROS integration and detector-adapter tests also passed inside the
virtual environment used by the live demo.

Reproduction and dependency pins are in the workspace's
[`supermap_bringup/README.md`](../../supermap_bringup/README.md).
Local evidence is under `results/supermap-d435i/`: `demo-1hz.log`,
`live-check.json`, `query-check.json`, and `map/`.

This closes the gap in physical RGB-D execution. Ground-truth accuracy,
identity stability under real motion, threshold tuning, moving-camera
odometry, and LiDAR-camera capture validation remain unmeasured.

## 3D quality and throughput follow-up

The initial 1 Hz demonstration above predates the quality/performance changes
below. A 31.5-second D435i recording produced 471 usable synchronized frames.
YOLOE detections were cached once and held fixed for the comparison, so the
measured changes come from 3D processing rather than different segmentation.
Warm YOLOE inference on that capture averaged 18.47 ms (p95 19.88 ms).

Saturated 65.535 m readings and background depth inside otherwise useful
masks inflated object bounds. The indoor profile now filters optical depth
to 0.15–6 m before both projection and geometric evidence, rejects masked
depths beyond `max(3 * MAD, 0.15 m)` from their median, and uses per-axis
2nd–98th percentile bounds with the existing voxel padding. Invalid depth
is unknown space and cannot establish removal. Generic defaults keep the
range/robust filters disabled; objects with real depth variation or thin
extremities can lose valid geometry under this profile.

Median active-object box extents in world XYZ, across the same capture:

| Label | Before (m) | Indoor profile (m) |
| --- | --- | --- |
| Chair | 63.58 × 33.13 × 4.89 | 0.51 × 0.55 × 1.00 |
| Monitor | 62.87 × 10.84 × 9.66 | 1.18 × 0.87 × 0.55 |
| Laptop | 32.50 × 10.71 × 0.83 | 0.63 × 0.50 × 0.29 |
| Keyboard | 1.09 × 0.43 × 0.09 | 0.62 × 0.41 × 0.09 |

The number of distinct chair IDs that reached active status fell from 17 to
2. These are plausibility and stability observations, **not ground-truth
accuracy measurements**. They aggregate per-label instances and frames;
they do not prove that every surviving box is correct.

The final CPU replay ran each configuration three times, sequentially, with
the live demo stopped. Timings cover pipeline processing (1,413 samples per
configuration), excluding image loading, detector execution, and ROS output:

| Pipeline cost | Before | Indoor profile |
| --- | ---: | ---: |
| Mean frame time | 23.32 ms | 20.29 ms |
| Median frame time | 23.22 ms | 20.11 ms |
| p95 frame time | 27.61 ms | 23.79 ms |
| Mean appearance embedding | 8.34 ms | 4.05 ms |

Masked RGB sampling now happens before copying pixels, and depth sampling
happens before allocating XYZ. The selected samples are unchanged. Evidence
updates avoid copying and rebuilding a box when no points are pruned. The
robust depth filter adds work, but the complete profile still reduced mean
pipeline time by 13% on this capture.

Live scheduling also changed: camera timestamp jitter no longer skips whole
detector/publication periods, completed inference wakes the ROS executor,
and tentative tracks age on completed detector misses rather than the faster
geometry-only stream. Unused full-map JSON serialization was removed from
every publication. The demo hides disappeared points/markers while retaining
their identity/history for persistence and queries (`show_history:=true`
restores the display).

An independent subscriber then measured 180.03 seconds of the final live
profile after warmup, with RViz running:

| Stream | Messages received | Mean rate |
| --- | ---: | ---: |
| RGB / aligned depth (each) | 2,571 | 14.28 Hz |
| Detector annotations | 2,566 | 14.25 Hz |
| Semantic points | 2,582 | 14.34 Hz |
| Box/label markers | 2,579 | 14.33 Hz |

Normal 30-second windows measured approximately 14.99 Hz input and
14.92–15.00 Hz annotations. One window dipped to 10.72 Hz input and 10.66 Hz
annotations; both recovered without a restart. Its cause was not isolated.
The full-interval averages above include it, and the independent topic
counts are not an exact per-frame delivery/loss audit. The node held roughly
12–13 instance records during this interval; the earlier progressive
slowdown did not recur. This is a short live check, not an hours-long or
large-map stability result.

Median image-stamp-to-subscriber latency was 79 ms for raw RGB, 141 ms for
annotations, and 124 ms for semantic points (p95 81/153/136 ms). The preceding
polling-based profile measured 190 ms median annotation latency and 12.39 Hz
annotations over 150 seconds. The live scenes differ, so that latency/rate
comparison is observational rather than a controlled scheduling benchmark.
Evidence: `quality-review/live-final.json`, `monitor.py`, and `demo.log`;
`live-filtered-polling.json` records the preceding run. The current saved
map is in `map/`; `quality-review/initial-smoke-map/` preserves the original
1 Hz smoke-test snapshot.

Validation: the full suite passed 212 tests in the live ROS/Python environment;
all 25 ROS tests passed again after adding the detector-completion wakeup.
The generic-default synthetic evaluation passed every existing CI metric
gate: detection recall 0.976, change recall 0.959, final-map F1 0.889, 12 IDs,
both relocation/return identities retained, mIoU without background 0.996,
and mAP50 1.000. The build of both ROS packages passed.
