# SuperMap review — 2026-09-24

A read-only review of the `jcfurey/SuperMap` fork at `63d9b6e` (branch `dev`).
It covered three areas:

- the ROS 2 layer, checked against ROS 2 and Nav2 conventions;
- the core mapping algorithms;
- the dense-cloud, perception, I/O and VLN modules.

At that commit, the unit tests (everything except `test/ros`) ran 318 passed.

Line numbers refer to `63d9b6e`. Each item has an ID so fixes can be tracked.
**Checked** means I read the code, or ran a snippet, and confirmed the problem.
**Suspected** means the code behaves as described but the real-world impact
depends on runtime conditions.

Every item fixed after the review is listed with its fix under
[Resolution](#resolution).

## 1. Correctness bugs

| ID | Location | Problem | Status |
|---|---|---|---|
| C1 | `pipeline.py:347, 417` | Unmatched tracks store the predicted Kalman state, but `latest_stamp` never advances. Each later frame without a detection therefore predicts again over the whole gap since the last match. After 30 such frames at 10 Hz the x variance is 8.2e6 px², against 1.1e4 for one correct 3 s prediction, and the Mahalanobis gate stops rejecting anything. Every frame between the 1 Hz detections takes this path. | Checked |
| C2 | `association.py:87-97`, `pipeline.py:379-389` | Stages 1 and 2 of association ignore labels. A `person` detection overlapping a chair's predicted box is fused into the chair, and `person` enters the chair's belief. That later lets it merge with real person instances. | Checked |

## 2. ROS 2 and Nav2 conventions

| ID | Location | Problem |
|---|---|---|
| R1 | `launch/semantic_mapping.launch.py:43-86` | `publish_static_camera_tf` defaults to true with a placeholder extrinsic. This conflicts with RealSense or URDF TF, or silently mis-calibrates the camera. |
| R2 | `dense_cloud_node.py:99`, `node.py:539-541, 701` | TF is looked up at the exact sensor stamp with no timeout or message filter, so clouds arriving before their TF are dropped. The listener in `dense_cloud_node` shares a callback group with the cloud callback. |
| R3 | `dense_cloud_node.py:115, 163`, `dense_yoloe_node.py:395` | Warnings and errors are logged at sensor rate without throttling. |
| R4 | `node.py:115, 230, 283`, `config/semantic_mapping.yaml:57` | `prompts_file` is resolved relative to the working directory. With `ros2 run`, the vocabulary is silently empty. |
| R5 | `config/*.yaml`, launch files | YAML keys are bare node names, topics are absolute and there is no namespace argument, so the stack can't be namespaced or remapped. |
| R6 | launch files | There is no `use_sim_time` argument. `dense_yoloe_node` has no launch file, and nothing uses `config/dense_yoloe.yaml`. |
| R7 | all nodes | Parameters have no descriptors, ranges or `read_only` flags, and there is no on-set callback. `ros2 param set` reports success but changes nothing. Integer values given for double parameters throw. |
| R8 | all nodes | These are plain nodes rather than lifecycle nodes, and models load in `__init__`. Nav2 expects managed nodes driven by `nav2_lifecycle_manager`. |
| R9 | `node.py:474-520` | The query interface is fire-and-forget `String` in and out, with no request ID and an unbounded job queue. It should be an action. The goal is the object's centroid, which is inside an occupied costmap cell. |
| R10 | `node.py:380-385` | Map outputs are published volatile with depth 10, which suits neither latched map data nor sensor-style streams. |
| R11 | `node.py:676` | An exception in the pipeline escapes the callback and kills the executor. |
| R12 | node outputs | There are no typed semantic outputs: annotations and metadata are JSON inside `std_msgs/String`. They should use `vision_msgs/Detection3DArray` plus custom messages. |
| R13 | all nodes | There is no `diagnostic_updater` (rates, TF failures, drops). |
| R14 | `package.xml` | `python3-opencv` and the test dependencies are missing. The ament linters are declared, but no linter tests exist. There is no LICENSE file, and the maintainer and URL still point upstream. |
| R15 | `docker/Dockerfile:80-86` | pip `ultralytics` pulls in `opencv-python`, which shadows apt `python3-opencv`. |
| R16 | all `main()`s | `ExternalShutdownException` is not handled. They use `rclpy.shutdown()` where `rclpy.try_shutdown()` is needed. |
| R17 | `node.py:791-793` | There is no `DELETEALL` marker on startup or map load, so stale boxes stay in RViz. |
| R18 | launch files | Every launch argument is always injected as a parameter, which shadows the YAML. Paths are built by string concatenation instead of `PathJoinSubstitution`. |
| R19 | `node.py:399-400` | Save and load use `std_srvs/Trigger`, so they take no path, and they run synchronously on the only executor thread. |
| R20 | `setup.py`, CI | CI never runs `colcon test`, and PRs run twice (`push` plus `pull_request`). The compose file reserves a GPU even for the lite image. |

## 3. Performance

| ID | Location | Problem |
|---|---|---|
| P1 | `association.py:183-208` | `reidentify` is an O(retired × detections) Python loop: 530 ms at the default 1000 retired instances. |
| P2 | `dense_cloud.py:145-191, 246-277`, `dense_cloud_node.py:234-250` | Every cloud re-segments the whole map. Every cloud and annotation batch then rebuilds the full result, the PointCloud2 and a per-region Python metadata loop. |
| P3 | `detectors/yoloe_detector.py:53-74` | The detector syncs the GPU once per box, copies float32 retina masks to the CPU before thresholding, and does not use `half=True`. |
| P4 | `ros_msgs.py` image decode | `bytes(msg.data)` + `astype` + `ascontiguousarray` make roughly three copies per frame. |
| P5 | `node.py:549, 572-583` | RGB is decoded at full rate, and `N` accumulated scans are re-concatenated and re-transformed on every frame. |
| P6 | `node.py:756-780` | The whole object cloud is republished at 5 Hz even when nothing changed. |
| P7 | `segmentation_metrics.py:124, 243-254` | Label transfer is O(I·N), and AP computes a per-pair IoU over all points. |
| P8 | `object_map.py:214-216` | The frustum test runs again for matched instances. |
| P9 | `node.py:741` | The mask overlay indexes each mask twice per detection. |

## Resolution

Every item above was fixed on branch `review-fixes-2026-09-24`.

**Layout.** The repo now holds two packages:

- `semantic_mapping/` (ament_python) is the old repo root, moved unchanged.
- `supermap_msgs/` (ament_cmake) is new and holds the typed interfaces. `semantic_mapping/semantic_mapping/ros_node_utils.py` holds the shared lifecycle, parameter and shutdown helpers.

**Tests.**

- `colcon test --packages-select semantic_mapping` passes: 480 tests, 0 failures, 1 skip (the copyright linter; upstream files carry no headers).
- The CI metric gate passes. The regression tests for the core algorithms are in `test/test_review_2026_09_24.py`; 39 of them fail against the original modules.

| Metric | Before | After |
|---|---|---|
| mean detection recall | 0.976 | 0.976 |
| mean change recall | 0.959 | 0.957 |
| final-map F1 | 0.889 | 0.889 |
| instance IDs created | 12 | 12 |
| identities kept | 2 | 2 |
| mIoU without background | 0.9965 | 1.000 |
| mAP50 | 1.0 | 1.0 |

Change recall dips because a removed object is now confirmed gone one frame later (C3 requires two contradicting frames).

### Correctness

| ID | Fix |
|---|---|
| C1 | Unmatched tracks keep the state from their last match, and each frame predicts once from `latest_stamp`. |
| C2, C20 | Association stages 1–2 gate on label belief mass and add a label cost. Compatibility everywhere (association, re-ID, merge, reconcile) uses `label_compatibility_min_mass` (0.1). |
| C3 | `prune_min_contradictions` (2) lowers the effective prune threshold. `contradiction_window_px` (1) uses min-depth over 3×3 at silhouettes. |
| C4, C28 | Annotation decoders type-check everything and raise only `ValueError`. There are caps on detections, pixels, mask area, label length, runs, message bytes and vocabulary (`max_labels`). |
| C5 | Two guards, both configurable: a 1/z splat footprint in the z-buffer (`camera_splat_*`), and per-mask nearest-depth-layer selection (`mask_depth_gap*`, `mask_min_layer_points`). |
| C6 | `stable_label_color` (sha256) is shared by `node.py` and `dense_yoloe_node.py`. |
| C7 | The robot pose is looked up at `Time()` (latest). Frame `robot_frame`; the warning is throttled. |
| C8 | A clock jump callback (plus detection of input stamps jumping back) resets input state and calls `SemanticMappingPipeline.begin_new_epoch()`. |
| C9, C10 | The converter's depth cache is reference-counted. The cloud→camera transform uses `lookup_transform_full` at the image stamp. |
| C11 | Map saves write `map_arrays-<ts>-<id>.npz`, then `map.json` as the commit marker. Both are temp file + fsync + `os.replace`. `save_result` renames the NPZ, then the JSON. Old `map_arrays.npz` maps still load. |
| C12 | A detector miss is charged only when the instance is in view and has observable points. |
| C13 | One label update per frame. Corroboration raises the likelihood (`P_SELF_CORROBORATED`). |
| C14 | The chroma histogram skips pixels below `min_intensity`; too few lit pixels gives no embedding. |
| C15 | Scene-graph neighbours are selected by box gap, not centroid distance. |
| C16 | New beliefs are `{label: 1.0}`. |
| C17 | Frames without depth still count detector misses, so tentative tracks expire. |
| C18 | `PipelineConfig.__post_init__` validates counts, ranges and positivity. |
| C19 | `process_frame` works on shallow copies of the caller's detections. |
| C21 | `reconcile_retired` is gated by `reconcile_max_distance_m` (10 m) and `reconcile_max_gap_sec` (120 s). |
| C22 | The point cap keeps points in tiers: evidence-bearing existing points, then other existing points, then new ones. The `ObjectMap` default is 5000. |
| C23–C26 | VLM errors all become `VLMError`, with bounded retries that honour `Retry-After`. The parser takes the last `<answer>` and ASCII digits only. `model`, `max_tokens` (16000), `max_retries` and `retry_backoff_s` are configurable, and hitting `max_tokens` is an explicit error. Labels and instructions are sanitised. |
| C27 | `dense_yoloe_node` catches any per-frame exception, logs it throttled and counts it. |
| C29 | Non-zero `D` is rejected unless `camera_images_rectified` is set, in which case `P` is the pinhole model. This applies in `node.py`, the dense nodes and the converter (`--rectified`). |
| C30 | The `.sens` reader validates the version, the header fields and every record length against the file size. |
| C31 | Map points are saved as float64. |
| C32 | `identity_consistency` requires the same majority ID in every phase. |
| C33, C34 | Separate callback groups on a MultiThreadedExecutor. The counters sit behind one lock. |
| C35 | Hashing is streamed. JSON is written with `allow_nan=False`; non-finite values become `null`. |
| C36 | The misalignment is documented in `datasets_scannet.py`. |
| C37 | The first frame after a load rebases stored stamps if they lie in the new epoch's future. |
| C38 | Workers are joined before the guard condition is destroyed under `_guard_lock`. `run_node` tolerates a repeated Ctrl-C. |

### Performance

| ID | Fix |
|---|---|
| P1 | `reidentify` is vectorised: 84 ms → 5.3 ms at 1000 retired × 10 detections, with identical matches. |
| P2 | Incremental surface-graph updates recompute a halo around changed voxels (about 2.6 s → 1.0 s per update at 200k voxels). Metadata is vectorised. Publishing is throttled by `publish_period_s`. |
| P3 | YOLOE makes one host transfer, thresholds masks on the GPU as bool, and runs with `half=True` on CUDA. |
| P4 | Images are decoded with `np.frombuffer`, copying exactly once. |
| P5 | RGB is decoded only for detector frames. Accumulated scans live in a preallocated ring and are transformed once each. |
| P6 | The object cloud is republished only when its content signature changes. |
| P7 | Label transfer uses lookup arrays, and AP uses one intersection matrix; results are identical to the old implementation. |
| P8 | The pipeline's batched in-view flag is passed through `update_matched`, `reactivate` and `update_unmatched`. |
| P9 | The mask overlay uses a single flat index. |
